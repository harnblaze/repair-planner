## Локальная база: никогда не `supabase db reset` для уборки

Локальная база — не только временные данные: пользователь сам логинится в dev-приложение (`http://localhost:3000`) и проверяет фичи между сессиями. `supabase db reset` проигрывает все миграции с нуля и сносит **всё**, включая его аккаунты, проекты и вручную заведённые данные. Выборочного режима у него нет.

После Playwright/curl-тестов, создавших мусорные строки, базу не сбрасывать: либо оставить тестовые строки (в dev это безвредно), либо удалить точечно — например `delete from auth.users where email = '<test email>'` (каскадом удалит своё). Полный reset — только если он действительно нужен и пользователь явно разрешил.

## UI-проверки в браузере

Если браузерная панель/вкладка скрыта, страница живёт с `document.visibilityState === "hidden"`: Chrome троттлит её, `loading="lazy"` изображения не грузятся, гидратация React может не завершиться. Скриптовые клики и `change`-события при этом молча ничего не делают и выглядят как баг приложения.

Перед выводом «это баг UI» проверить `document.visibilityState`; если `hidden` — сначала заставить страницу отрисоваться (скриншот), потом повторять проверку.

## Что нового: правило

- Любое изменение, заметное пользователю (новая функция, изменение поведения, исправленный баг), сопровождается записью в `lib/business/changelog.ts`. Новые записи — сверху.
- Текст — для мастера: что теперь можно сделать иначе или лучше. Без технических деталей, без имён файлов и слов вроде «Realtime», «RLS», «миграция».
- Внутренние изменения (рефакторинг, миграции без видимого эффекта, тесты, деплой) записей не требуют.
- В одной записи — одна тема; `id` не переиспользовать; дата — день выкатки.
