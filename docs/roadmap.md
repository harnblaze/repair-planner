## Открытые вопросы

Ни один из них не блокирует этапы 1–2.

| Вопрос | Когда нужен ответ |
|---|---|
| Должен ли перенос быть автоматическим (незавершённые задачи сами переезжают на следующий рабочий день) или только по действию мастера? Решено: только вручную, кнопка «Перенести на следующий рабочий день» в карточке задачи (этап 8). | Решено |
| Нужна ли задаче плановая трудоёмкость или срок от заказчика (дедлайн)? В MVP не закладывается. | После MVP |
| Нужно ли ограничивать список исполнителей, доступных для выбора, только активными? Да, с возможностью показать архивных (реализовано на этапе 6). | Решено |
| Как показывать задачу, запланированную на прошедшую неделю и незакрытую? Решено: оставлять в той неделе, где запланирована; отдельного «просроченного» вида в MVP нет. Перенос — ручное действие мастера, этап 8. | Решено |
| Нужны ли toast-уведомления об успехе/ошибке мутаций (вместо только инлайн-текста у формы)? Решено: да, добавлен sonner (этап 11). Для непрерывного инлайн-редактирования (автосохранение по blur/onChange: название/описание/категория/дата плана задачи, выбор исполнителей) — только toast об ошибке, без toast об успехе, чтобы не быть навязчивым при частом редактировании. | Решено |
| Возвращать ли статус `planned` → `new` при снятии задачи с плана (перетаскиванием или очисткой даты)? Сейчас статус не меняется, и в «Текущих заявках» задача может показываться как «Запланирована». | При необходимости |
| Нужен ли в отчёте «цех на момент списания» вместо текущей категории заявки? Требует `category_id` в `material_movements`. | При необходимости |
| Нужны ли в отчёте итог по материалу по всем цехам, разбивка по заявкам, оборотная ведомость (остаток на начало/конец, приход) и печать? | При необходимости |
| Нужен ли перенос записей между дополнительными списками и сортировка «Текущих заявок»? Для второго нужна колонка позиции в `tasks`. | При необходимости |
| Нужен ли приход задним числом (дата накладной) и оборотная ведомость (остаток на начало/конец месяца, приход, расход)? Сейчас движение датируется моментом записи. | При необходимости |
| Удаление проекта с расходом материалов падает: при каскадном удалении `task_materials` триггер пишет движение в удаляемый проект. В UI удаления проекта нет (только через API владельцем), данные не портятся. Нужно решить, удалять ли проекты вообще или только архивировать, и поправить триггер. | До появления удаления проекта в UI |
| На экране шириной ~400px навигация проекта (`ProjectNav`) выходит за ширину страницы и даёт горизонтальный скролл на всех страницах проекта. | При необходимости |
| Нужна ли передача владения проектом другому участнику? Сейчас роль `owner` не выдаётся и не отнимается. | При необходимости |
| Нужны ли приглашения письмом (Supabase Auth `inviteUserByEmail`)? Требует `service_role` на сервере и настроенный SMTP; сейчас ссылку владелец отправляет сам. | При необходимости |
| Если в production включено подтверждение email, после регистрации по ссылке-приглашению `next` теряется: получатель подтверждает почту, входит и открывает ссылку заново. Можно передавать `next` в `emailRedirectTo`. | До включения подтверждения email |
| Нужна ли редактору (`member`) возможность приглашать участников с ролью «Только просмотр»? Сейчас приглашает только владелец. | При необходимости |
| Нужно ли заполнять переносы выходных по постановлению Правительства автоматически (например, ежегодно обновляемым списком)? Сейчас кнопка добавляет только фиксированные праздники ТК РФ, выпавшие на Пн–Пт; переносы мастер вносит сам. | При необходимости |
| Нужно ли массово переносить заявки с дня, который объявили нерабочим? Сейчас заявки остаются на месте, мастер получает предупреждение и переносит их по одной. | При необходимости |
| Нужны ли рабочие воскресенья? Не поддерживаются: CHECK разрешает `working_day` только в субботу, на доске нет колонки «Вс». | При необходимости |
| Поле даты в карточке для уже запланированной заявки заменяет план двумя запросами (удаление, затем вставка) — не атомарно. Рабочий день проверяется до удаления, но сбой вставки по другой причине оставит заявку без плана. Кандидат на RPC. | При необходимости |
| Как адаптировать доску (5 рабочих дней + доп. списки) под мобильный экран? Решено: оставить вертикальный список колонок (текущее поведение при схлопывании грида) без табов по дням — не создаёт горизонтального скролла, минимальное изменение. | Решено |

## После MVP

Порядок ориентировочный, реализуется только по отдельному запросу.

1. ~~Месячный отчёт по расходу материалов~~ — сделано (этап 13).
2. ~~UI прихода и корректировки материалов~~ — сделано (этап 14).
3. ~~Приглашение пользователей в проект, роль `viewer`~~ — сделано (этап 15).
4. ~~Drag-and-drop на доске~~ — сделано (этап 12).
5. ~~Праздники и производственный календарь~~ — сделано (этап 16, таблица `project_calendar_days` вместо `holidays`).
6. Пользовательские дополнительные списки.
7. Вложения к задачам (Supabase Storage).
8. Фильтры и поиск по задачам, архив выполненных работ.
9. Индивидуальные графики исполнителей, загрузка по дням.

## Отклонённые идеи

| Идея | Причина |
|---|---|
| Сущность «склад» | Прямо исключена требованиями; материалы принадлежат проекту |
| Таблица `holidays (project_id, date)` | Не выражает рабочие субботы производственного календаря; выбрана `project_calendar_days` с видом исключения |
| Полный производственный календарь РФ с переносами, зашитый в код | Требует ежегодного обновления по постановлению Правительства; устаревшие данные молча ломают планирование. Выбраны фиксированные праздники ТК РФ + ручные переносы |
| `planned_quantity` у материала в задаче | Учитывается только фактический расход |
| Чистый event sourcing для остатков | Избыточно для MVP, усложняет каждый запрос доски |
| Отдельная таблица `task_transfers` | `task_schedule` уже является историей переносов |
| «Текущие заявки» как запись в `board_lists` | Обеднило бы модель задач ради формальной универсальности |
| Drag-and-drop в MVP | Закрывался быстрыми действиями; добавлен после MVP (этап 12) |
| Добавление участника по email существующего пользователя | Позволяет перебором узнать, зарегистрирован ли email; выбрана ссылка-приглашение |
| Хранение токена приглашения в открытом виде (повторный показ ссылки) | Утечка таблицы раскрыла бы действующие ссылки; хранится sha256, ссылка показывается один раз |
| Копия заявки при откладывании | Нарушает идентичность задачи (CLAUDE.md §27), раздваивает материалы и отчёты; вместо неё — `task_schedule.postponed` |
