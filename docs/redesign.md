# Handoff: Repair Planner — visual redesign

## Overview
Визуальный редизайн существующего веб-приложения Repair Planner (недельный планировщик работ ремонтно-строительного цеха). Структура интерфейса, навигация, бизнес-логика и набор функций **не менялись** — переработаны только оформление, типографика, spacing, состояния элементов и визуальная иерархия.

Задача разработчика: применить этот визуальный слой к существующему приложению, **не трогая** разметку потоков, роутинг и бизнес-логику.

## About the Design Files
Файл `Repair Planner.dc.html` в этом пакете — **дизайн-референс, сделанный в HTML**. Это прототип, показывающий итоговый вид, а не production-код для копирования. Данные в нём захардкожены (тестовый набор из скриншота), обработчики не подключены.

Нужно воспроизвести этот дизайн в существующем окружении приложения (React / Vue / шаблоны сервера — что уже используется), опираясь на принятые в проекте паттерны и библиотеки. Если окружения нет — выбрать подходящее и реализовать там.

## Fidelity
**High-fidelity.** Финальные цвета, типографика, spacing и состояния. Воспроизводить попиксельно, значения ниже — нормативные.

## Interactions & Behavior
Поведение не меняется относительно текущего приложения. Визуальные состояния, которые нужно реализовать:

- **Кнопки primary** (`Добавить`): фон accent, текст `#FFFFFF`, 12.5px / 600, высота 30px, padding 0 12px, radius 7px, слева иконка «+» 11×11 (stroke 2). Hover `filter: brightness(1.08)`, active `brightness(0.94)`, focus — кольцо `0 0 0 3px rgba(47,85,200,0.12)`, disabled — фон `#C8D0DE`, курсор default.
- **Кнопки secondary** (недели): см. §3; disabled — текст `#A6AEBB`.
- **Ссылки навигации** (tertiary): только hover-фон, без рамок.
- **Inputs / select**: высота 30px, padding 0 10px, 12.5px, border `1px solid #D9DFE8`, radius 7px, фон `#FFFFFF`, placeholder `#9AA4B2`. Hover border `#C4CDDA`. Focus: border accent + `box-shadow: 0 0 0 3px rgba(47,85,200,0.12)`, `outline: none`.
- **Карточки и элементы списков**: hover — см. выше. Анимаций и переходов сложнее `transition: 120ms ease` не требуется; drag-and-drop не вводить.

## State Management
Новых состояний дизайн не вводит. Достаточно того, что уже есть:
- текущая неделя (диапазон дат, навигация назад/вперёд);
- задачи по дням с полями: название, статус, исполнитель/объект, признак и дата переноса;
- списки: заявки (+ выбранная категория в select), материалы, напоминания, мероприятия;
- значение «сегодня» — для подсветки колонки текущего дня (если день вне показанной недели — подсветки нет).

## Responsive
Только desktop, мобильной версии нет. Композиция сохраняется на 1440 / 1280 / 1024px: пять колонок и четыре нижние панели не переносятся и не схлопываются. При сужении уменьшаются gaps и внутренние padding (например, gap нижней сетки 14 → 10px, padding колонки 10 → 8px). Сетки заданы через `minmax(0, 1fr)` — это обязательно, иначе колонки распираются длинным текстом.

## Assets
Внешних ассетов нет. Все иконки — inline SVG 11–13px, stroke 1.4–1.6, `stroke-linecap: round`: календарь, закладка, коробка, колокол, часы, плюс, стрелка переноса, chevron. При наличии в проекте своей icon-библиотеки (Lucide / Feather и т.п.) взять эквиваленты оттуда и сохранить размер и толщину штриха.

Шрифты подключаются через Google Fonts:
`https://fonts.googleapis.com/css2?family=IBM+Plex+Sans:wght@400;500;600;700&family=IBM+Plex+Mono:wght@400;500&display=swap`
