# Архив выполненных работ и поиск по нему — дизайн

Дата: 2026-10-08. Статус: на согласовании. Roadmap «После MVP», п. 8.

## 1. Цель

Мастер находит прошлую работу: «что мы делали для Механического в сентябре,
кто делал». Для этого на странице «Заявки» появляется вкладка «Архив» —
выполненные и отменённые заявки с поиском по тексту, периоду, цеху и
исполнителю.

Сейчас `app/(app)/[projectId]/tasks/page.tsx` загружает **все** заявки проекта
без пагинации, закрытые лежат в свёрнутом блоке «Завершённые и отменённые»,
поиска и фильтров нет.

Фильтры открытых заявок, отчёт «выполнено за период» и поиск по материалу в
этот этап не входят (§9).

## 2. Решения, принятые с пользователем

| Вопрос | Решение |
|---|---|
| Главный сценарий | Найти прошлую работу. |
| Критерии первой версии | Текст (название и описание), период выполнения, цех, исполнитель. Материал — нет. |
| Где | Вкладка «Архив» на странице «Заявки», рядом с вкладкой «Открытые». |
| Что в архиве | Выполненные (`completed`) и отменённые (`cancelled`) заявки. |
| Отменённые и период | У отменённой нет даты выполнения. Если задана хотя бы одна дата периода, показываются только выполненные. Отменённые видны, только когда период не задан. |
| Статус по умолчанию | «Выполненные». Переключатель: «Выполненные», «Отменённые», «Все». |
| Реализация | SQL-функция поиска (вариант 1). Запросы supabase-js со страницы и полнотекстовый поиск отклонены (§8). |
| Как ищется текст | Вхождение подстроки без учёта регистра, без морфологии. |

## 3. Данные — миграция `0020_search_archive_tasks.sql`

Таблицы и колонки не меняются. Миграция создаёт одну функцию.

```sql
public.search_archive_tasks(
  p_project_id  uuid,
  p_status      text,   -- 'completed' | 'cancelled' | 'all'
  p_query       text,   -- null или пусто — без текста
  p_category_id uuid,   -- null — все цеха
  p_executor_id uuid,   -- null — все исполнители
  p_from        date,   -- null — без нижней границы
  p_to          date,   -- null — без верхней границы, включительно
  p_limit       int
) returns table (
  id             uuid,
  title          text,
  status         text,
  completed_at   timestamptz,
  category_name  text,
  executor_names text[]
)
language sql stable security invoker set search_path = ''
```

**Права.** Функция работает с правами вызывающего (`security invoker`), RLS
`tasks`, `categories`, `executors` и `task_executors` действует как обычно.
Чужой или несуществующий проект даёт пустой результат, не ошибку.
`revoke all ... from public, anon; grant execute ... to authenticated` — как у
остальных функций проекта (0016).

**Фильтры.**

- Статус. Если задан период (`p_from` или `p_to` не null), фильтр всегда
  `status = 'completed'`, независимо от `p_status`. Иначе `completed`,
  `cancelled` или оба для `all`. Другое значение `p_status` →
  `raise exception 'invalid_filter'`: приложение передаёт только проверенные
  значения, ошибка означает баг.
- Текст. `btrim(p_query)`; пусто → без фильтра. Иначе
  `title ilike '%' || q || '%' or description ilike '%' || q || '%'`, где в `q`
  экранированы `\`, `%` и `_` (в этом порядке) обратной косой чертой.
- Цех. `t.category_id = p_category_id`. В списке фильтра есть и архивные цеха.
- Исполнитель. `exists (select 1 from public.task_executors te where
  te.task_id = t.id and te.executor_id = p_executor_id)`. В списке фильтра есть
  и неактивные исполнители.
- Период. Границы — полночь в timezone проекта, как в
  `material_consumption_by_category` (0009):
  `completed_at >= p_from::timestamp at time zone p.timezone` и
  `completed_at < (p_to + 1)::timestamp at time zone p.timezone`.

**Порядок.** `coalesce(t.completed_at, t.updated_at) desc, t.id`. Выполненные —
по дате выполнения, отменённые — по последнему изменению.

**Лимит.** `least(greatest(p_limit, 1), 1001)`. Страница просит на одну строку
больше, чем показывает, чтобы узнать, есть ли продолжение.

**Колонки результата.** `category_name` — `left join categories`.
`executor_names` — `array(select e.name ... order by e.name)` по
`task_executors`, пустой массив, если исполнителей нет.

**Индексы.** Не добавляются: заявок десятки в месяц, существующий
`tasks_project_status_idx (project_id, status)` достаточен. Триграммный индекс
pg_trgm для текста — в roadmap на тысячи заявок.

## 4. Сервер приложения

### 4.1 Разбор параметров — `lib/validation/archive-filters.ts`

Схема Zod `archiveFiltersSchema` разбирает `searchParams` вкладки архива:

| Параметр | Значение | По умолчанию |
|---|---|---|
| `view` | `archive` (иначе вкладка «Открытые») | — |
| `q` | строка, `trim`, до 100 символов | пусто |
| `status` | `completed` / `cancelled` / `all` | `completed` |
| `category` | `idSchema` | все |
| `executor` | `idSchema` | все |
| `from`, `to` | `YYYY-MM-DD`, существующая дата (`isValidDateString`) | нет |
| `page` | целое 1–20 | 1 |

Некорректное значение не даёт ошибку: поле молча получает значение по
умолчанию (адрес могли отредактировать руками). Каждое поле разбирается
отдельно, одно неверное поле не сбрасывает остальные. Если `from > to`, даты
меняются местами. Текст длиннее 100 символов обрезается до 100.

Функция `parseArchiveFilters(searchParams): ArchiveFilters` и обратная
`archiveQuery(filters, overrides?): string` (строка `URLSearchParams` без полей
по умолчанию — для ссылок «Этот месяц», «Показать ещё», вкладок).

### 4.2 Быстрые периоды — `lib/business/archive-periods.ts`

`monthRange(today: string, offset: 0 | -1): { from: string; to: string }` —
первый и последний день текущего или прошлого месяца по дате `today` в
timezone проекта (`todayInTimezone`). Чистая функция на строках
`YYYY-MM-DD`, без `Date` в часовом поясе браузера.

### 4.3 Загрузка — `app/(app)/[projectId]/tasks/archive-data.ts`

`loadArchive(projectId, filters)` вызывает `rpc("search_archive_tasks", …)` с
`p_limit = filters.page * 50 + 1`, возвращает
`{ tasks: ArchiveTask[], hasMore: boolean }`. Ошибка RPC пишется в
`console.error` и превращается в `{ error: "Не удалось загрузить архив. Обновите страницу." }`.
Справочники для фильтров (`categories` и `executors` проекта, включая
архивных, сортировка по имени) грузятся параллельно.

## 5. Интерфейс — страница «Заявки»

`app/(app)/[projectId]/tasks/page.tsx` остаётся Server Component.

- **Вкладки.** Сегментированная пара ссылок «Открытые» / «Архив» (стиль
  сегментов недели на доске). `?view=archive` — архив.
- **Открытые.** Как сейчас: форма создания (для редактора) и список открытых
  заявок. Запрос загружает только открытые заявки
  (`status not in ('completed','cancelled')`). Блок «Завершённые и отменённые»
  удаляется — эти заявки теперь в архиве.
- **Архив** — `tasks/archive-filters.tsx` и `tasks/archive-list.tsx`, оба
  серверные компоненты.
  - Фильтры — GET-форма (`<form method="get">`, скрытое поле `view=archive`):
    поиск (`type="search"`, placeholder «Название или описание»), статус, цех
    («Все цеха» + цеха, архивные с пометкой «(архив)»), исполнитель («Все
    исполнители» + исполнители, неактивные с пометкой «(архив)»), даты «с» и
    «по» (`type="date"`), кнопка «Найти», ссылка «Сбросить» (`?view=archive`).
  - Под формой ссылки «Этот месяц» и «Прошлый месяц» — сохраняют остальные
    фильтры, задают `from`/`to`.
  - Если период задан, рядом со статусом подпись «Период — по дате
    выполнения, показаны только выполненные»; выбор статуса не блокируется,
    но правило §2 применяет функция.
  - Строка результата — ссылка на карточку заявки: название; ниже
    «цех · исполнители» (`text-meta`); справа дата выполнения `ДД.ММ.ГГГГ`
    в timezone проекта или «Отменена». Отменённая — название приглушено и
    зачёркнуто, как сейчас.
  - Под списком «Показать ещё» — ссылка с `page = N + 1`, если `hasMore` и
    `page < 20`. На 20-й странице вместо ссылки подсказка «Уточните условия
    поиска».
  - Пусто: «Ничего не найдено. Измените условия поиска.» Пустой архив без
    фильтров: «Выполненных заявок пока нет.»
- **Ширина.** `max-w-lg` → `max-w-3xl`. Фильтры — сетка: на телефоне в
  столбик, от `sm` — в две-три колонки. Горизонтальной прокрутки на 375 нет.

Клиентского JavaScript вкладка архива не добавляет.

## 6. Проверка

- pgTAP `supabase/tests/database/archive-search.test.sql`:
  - статус по умолчанию и `all`, `cancelled`;
  - период включает обе границы и считается в timezone проекта (заявка,
    выполненная 31-го в 23:30 по Москве, попадает в «по 31-е» и не попадает в
    «с 1-го» следующего месяца);
  - заданный период исключает отменённые даже при `p_status = 'all'`;
  - текст ищется в названии и описании без учёта регистра; `%` и `_` в
    запросе ищутся буквально;
  - фильтр по исполнителю и по цеху;
  - сортировка и лимит;
  - пользователь без доступа к проекту получает 0 строк; `invalid_filter`;
  - `anon` не может вызвать функцию.
- vitest: `archive-filters.test.ts` (разбор, значения по умолчанию, обмен
  `from`/`to`, обрезка текста, `archiveQuery`), `archive-periods.test.ts`
  (январь → прошлый месяц декабрь прошлого года, февраль високосного года).
- Браузер, 1280 и 375: вкладки, каждый фильтр, быстрые периоды, «Показать
  ещё», сброс, переход в карточку, пустые состояния, консоль без ошибок.
- tsc, eslint, `npm run build`, все тесты.

## 8. Отклонённые варианты

- **Запросы supabase-js со страницы без миграции.** Текст пришлось бы
  вставлять в синтаксис фильтра PostgREST `or(...)`, где запятые и скобки
  запроса ломают фильтр; фильтр по исполнителю через `!inner` меняет вложенные
  данные; границы периода считались бы в JS. Хрупко.
- **Полнотекстовый поиск с русской морфологией (`tsvector`).** Нужны колонка,
  индекс, словарь; при десятках заявок в месяц избыточно. Добавляется позже
  без изменения интерфейса.
- **Отдельная страница «Архив» в навигации.** Лишний пункт меню; архив — это
  те же заявки.
- **Бесконечная прокрутка.** Требует клиентского компонента; ссылка «Показать
  ещё» проще и работает без JS.

## 9. Вне объёма (в roadmap)

- Фильтры открытых заявок (цех, исполнитель, статус, очередь — п. 14).
- Поиск по материалу.
- Отчёт «выполненные работы за период» с выгрузкой.
- Триграммный индекс (pg_trgm) для текстового поиска — при тысячах заявок.
- Дата отмены заявки (`cancelled_at`), чтобы отменённые попадали в период.
